# ListenBrainz / Troi: проверка и выборочное применение

Проверка 28 октября 2026. Исходная версия Forma: `3f1e551`, Windows 1.20.0 / iOS 1.12.0.

## Решение

Полностью заменять персональный ранжировщик на Troi по результатам этой проверки нельзя: преимущество на личной библиотеке не установлено. После уточнения задачи «взять только полезное» подготовлен дополнительный источник кандидатов для обеих платформ. Текущие публичные EXE/IPA этим PR не заменяются.

Troi полезен архитектурой потоков кандидатов и доступом к связям артистов ListenBrainz. В Forma добавлен независимый клиент публичных API: найти точную личность исполнителя → получить похожих исполнителей → найти их записи на YouTube → проверить личную совместимость. Перевода или копирования GPL-кода Troi в приложение нет.

## Что действительно проверено

Прочитаны исходники Troi на ревизии [`044398b5`](https://github.com/metabrainz/troi-recommendation-playground/tree/044398b5b6c6c99fc301f3417e62570b2a408a40):

- [`LBRadioArtistRecordingElement`](https://github.com/metabrainz/troi-recommendation-playground/blob/044398b5b6c6c99fc301f3417e62570b2a408a40/troi/patches/lb_radio_classes/artist.py) получает популярные записи исходного и похожих артистов и чередует потоки.
- [`RecordingSearchByArtistService`](https://github.com/metabrainz/troi-recommendation-playground/blob/044398b5b6c6c99fc301f3417e62570b2a408a40/troi/recording_search_service.py) обращается к `/1/lb-radio/artist/{mbid}` с режимом и диапазоном популярности.
- [`UserRecordingRecommendationsElement`](https://github.com/metabrainz/troi-recommendation-playground/blob/044398b5b6c6c99fc301f3417e62570b2a408a40/troi/listenbrainz/recs.py) получает уже рассчитанные рекомендации пользователя ListenBrainz. Локальные лайки Forma сами по себе не создают такой профиль.
- [Справочник LB Radio](https://github.com/metabrainz/troi-recommendation-playground/blob/044398b5b6c6c99fc301f3417e62570b2a408a40/docs/lb_radio.rst) описывает выбор источников и диапазонов; глобальные плейлисты содержат MusicBrainz ID и требуют разрешения в воспроизводимые записи.
- [Официальная схема API](https://listenbrainz.readthedocs.io/en/latest/users/api/core.html) подтверждает формат пула записей. Счётчик прослушиваний не считается оценкой личной релевантности.

Живой прогон запущен для ксюшеньки, бэи, Трёх дней дождя и MARKUL. Все четыре lookup завершились транспортной ошибкой. Контрольный запрос через штатный прокси получил `Tunnel connection failed: 403 Forbidden`. Текущая политика среды разрешает GitHub/пакетные источники, но не MusicBrainz/ListenBrainz. Доступный веб-инструмент также не смог получить результаты динамических API-запросов.

**Это четыре недоступных запроса, а не четыре отсутствующих артиста.** Покрытие похожих артистов, русскоязычная доля, реальная скорость API, разрешение в YouTube и превосходство над нынешним Пульсом не измерены. Частные лайки, история и перенесённый плейлист пользователя в этой среде отсутствуют. Процент угадывания вкуса не вычислялся.

[Машинный отчёт живого прогона](verification/listenbrainz-coverage-2026-10-28.json) сохраняет статусы, публичные имена, URL и время; `personalTasteAccuracy: null`, `decision: do_not_replace_yet`.

## Что перенесено в Forma

| Принцип | Реализация |
|---|---|
| Личные источники кандидатов | Поиск похожих артистов начинается от положительных ориентиров активной библиотеки/плейлиста. Отправляется имя артиста, без аккаунта, токена, истории и файла библиотеки. |
| Надёжная идентичность | Принимаются точное нормализованное имя и точный псевдоним. Несколько подходящих MBID откладываются; первый нечёткий результат не принимается. |
| Независимые музыкальные связи | Метка `listenbrainz-neighbour` и родительский трек сохраняют происхождение. Связь артистов не записывается как `directRelatedTo` между конкретными песнями. |
| Проверка звучания/жанра | Дополнительная связь допускается при совместимом определённом жанре обеих записей или нейронном сходстве ≥0.85 при отсутствии сравнимого жанра. Противоречие нейронных признаков <0.65 отклоняет связь. Поисковые жанры и одинаковый темп не служат подтверждением. |
| Защита личного вкуса | Исходный ранжировщик, обучение по реакциям, 70/30, вся знакомая библиотека, настроение, свежие релизы, дизлайки, запреты стилей и артистов продолжают применяться. Новый источник не даёт исключений из этих правил. |
| Разнообразие | За проход обрабатываются максимум два похожих артиста и по 12 точно совпавших записей. Следующие проходы перебирают остальных артистов, а не постоянно первые два. |
| Скорость и отказоустойчивость | Холодное обращение возвращает пустой кеш сразу и запускает фоновую работу отдельно от потока/плеера. Один запрашиваемый артист одновременно, общий интервал ≥30 секунд; до 64 кешированных артистов. Успешный непустой кеш — 7 суток, пустой — до суток, сбой — 10 минут. Ответы ограничены 2 МиБ, сетевые запросы имеют таймауты. |
| Сбой внешнего сервиса | Продолжают работать прежние источники YouTube. Пустой необязательный ответ не скрывает полный отказ основного каталога. Неизвестные жанры остаются неизвестными. |

На Windows API работает в Electron через отдельный клиент; на iOS — в отдельном actor и фоновой задаче. Холодный кеш заполняется для следующего обновления, поэтому мгновенное появление новых артистов после первого запуска не обещается. Кеш ограничен памятью текущего запуска.

## Как завершить живое сравнение

Для прямых запросов среды нужны разрешённые `musicbrainz.org` и `api.listenbrainz.org`. При исследовании дополнительных Labs-связей — также `labs.api.listenbrainz.org`. Политика не обходится сторонним прокси или запуском запросов на другой машине.

```sh
node --use-env-proxy scripts/audit-listenbrainz.mjs --output /tmp/listenbrainz-audit.json
```

Node 24+, GET-запросы; без изменения приложения или внешнего профиля. Между запросами выдерживается ≥1.1 с. JSON содержит результаты и контрольные суммы успешных ответов; код выхода 2 означает незавершённую проверку, а не успешное сравнение.

После проверки покрытия нужны совпавшие записи YouTube, реальная библиотека и независимые оценки кандидатов. Сравнивать следует одинаковые музыкальные ориентиры и одинаковый период: долю подходящих находок, запрещённые жанры, новых артистов, повторы и задержку пополнения. Популярность, самооценка алгоритма и доля уже известных треков не доказывают улучшение. До такого результата полная замена Пульса не считается обоснованной.
