# Проверка Windows 1.9.0 / iOS 1.3.0

11 октября 2026. [Нативная CI-проверка](https://github.com/Astronomial/music/actions/runs/38165415964).

## Подтверждённый обмен по Wi-Fi

Google-модули и IPC удалены; прежние локальные OAuth-реквизиты очищаются без обращения к Google. При подключении готовится только просмотр. Для переноса каждого пакета требуется «Применить на обоих устройствах» на ПК или iPhone; одного подтверждения достаточно.

Проверены отсутствие записи при подготовке/опросе, отклонение, точное применение просмотренного пакета, отказ при изменении ПК после просмотра, принадлежность пакета телефону, повторные запросы, сохранение решений и получение после перезапуска, восстановление журнала уже подтверждённой записи, истечение срока и некорректные данные. Поздние правки телефона сохраняются при объединении. Старый автоматический `/sync` возвращает 426.

- `npm run test:ui`: **5/5 сценариев**, включая управление громкостью, рекомендации, дизлайки, настоящее декодирование AAC/PCM и подтверждение обмена. Каталог/YouTube-плеер и парный транспорт в UI-сценариях контролируемые.

## Проверки iOS

**75 тестов ядра**, **21 тест аудиопути**, отдельные Release-замеры ранжирования и выбора, Simulator Debug и iPhone Release arm64. Генератор проекта проверяет 18 Swift-файлов. IPA: iOS 17+, версия 1.3.0, сборка 9, фоновое аудио, без подписи Apple.

Подготовка трёх треков проверена настоящими AVQueuePlayer/AVPlayerItem. Дополнительные плееры остаются без звука и с нулевой скоростью; при выборе активируется уже подготовленный владелец элемента, без переноса AVPlayerItem между плеерами. Обычная очередь сохраняет автоматический переход. Старые наблюдатели не управляют новым активным плеером.

В сценарии два будущих трека читаются по HTTP, сервер задерживает каждое тело на **4 секунды**. Текущий файл длится 40 секунд, поэтому подготовка не ждёт его окончания. Моделируется доступная мобильная/дорогая сеть с флагом Low Data Mode; глубина остаётся три. После подготовки выбирается третий будущий трек:

| Замер от выбора до движения позиции готового аудио | Результат |
| --- | --- |
| Третий подготовленный HTTP-трек | **124.6 мс**, предел 350 мс |
| Ближайший подготовленный трек | **145.7 мс**, предел 250 мс |
| Контролируемый холодный старт с задержкой получения потока | **1422.5 мс**, предел 2500 мс |

Повторного получения потока третьего трека нет. Проверены сброс старых буферов при смене маршрута, сохранение ручной паузы, восстановление после сетевой смены/прерывания/сброса аудиосервиса, быстрые выборы, фоновые автоматические переходы, системное управление, ревизии сохранений и мини-плеер над вкладками. Нативный отчёт содержит 4 старта и 3 перехода/события очереди.

## Практические границы

Эти миллисекунды относятся к контролируемому аудио в симуляторе, не к живому YouTube или физическому iPhone 11. Сеть Linux-среды блокирует YouTube; Yota с пользовательским VPN здесь недоступны. Подготовка ускоряет уже готовые треки, но новый результат поиска требует получения потока. Windows EXE собран в Linux; его запуск на физической Windows здесь не проверен.

При обновлении сохраняй прежние Apple ID и фактический Bundle ID Sideloadly. [Установка](../ios/INSTALL_WINDOWS.md) · [Wi-Fi с подтверждением](WIFI_SYNC.md) · [звучание и дизлайки](SOUND_RECOMMENDATIONS.md).
