# Forma iOS 1.1.0

Нативное приложение **SwiftUI + AVQueuePlayer** для iPhone и iPad с **iOS 17+**, включая iOS 18. Онлайн-каталог YouTube/YouTube Music, персональный Пульс, плейлисты, подборки по настроению и синхронизация с Windows. Музыкальная подписка, аккаунт YouTube и обязательный сервер не требуются.

**[Скачать IPA для подписи](https://github.com/Astronomial/music/releases/download/ios-v1.1.0/Forma-iOS-1.1.0-unsigned.ipa)** · **[Установка с Windows](INSTALL_WINDOWS.md)** · [Лицензии](THIRD_PARTY.md)

IPA предназначена для устройства и подписывается своим Apple ID через Sideloadly. Бесплатная личная подпись обычно действует 7 дней; инструкцией предусмотрено обновление поверх приложения с сохранением данных. Это самостоятельная установка, не публикация в App Store.

## Возможности

- Тёмный стеклянный интерфейс, мягкие градиенты, четыре палитры, системные масштабируемые шрифты. Главная, поиск, библиотека, настройки, мини-плеер и полноэкранный плеер.
- Поиск по названию и артисту с задержкой 350 мс, отменой устаревших результатов и открытием прямой YouTube-ссылки отдельной кнопкой.
- AAC/M4A в нативной очереди. Следующий поток и `AVPlayerItem` готовятся заранее; временные URL кешируются с учётом срока действия. Устаревшие разрешения потока не заменяют новый выбор пользователя.
- Фоновая аудиосессия, системные play/pause/next/previous/seek, сведения на экране блокировки, реакция на звонки, отключение наушников, сброс аудиосистемы и смену сети. После смахивания приложения из переключателя воспроизведение прекращается.
- Пульс учитывает любимое, выбранные плейлисты, дослушивания, ранние пропуски и текущую сессию. Журнал фактически начавшихся треков регулирует расстояние между артистами; альтернативные загрузки одной записи объединяются, ремиксы сохраняются. Новые исполнители получают место в очереди при наличии подходящих кандидатов. Ошибки потока и перемотка не искажают вкус.
- Общий профиль для шести настроений, раскрывающиеся настройки жанров/исключений, энергии, вокала, открытий, разнообразия, повторов и плейлистов. Пульс можно запустить от своего плейлиста.
- Создание, переименование, удаление плейлистов; добавление и удаление треков; любимое. Метаданные/история сохраняются атомарно с резервной копией, есть JSON-экспорт.
- Двусторонняя синхронизация с **Forma Windows 1.6+** в домашней сети: любимое, YouTube-плейлисты, история, исключения и настройки Пульса. TLS с закреплённым сертификатом, одноразовое подключение, Keychain, объединение конкурентных изменений, сохранение изменений без сети. Локальное аудио и API-ключи остаются на ПК.

Неофициальное получение YouTube-потоков через [YouTubeKit](https://github.com/alexeichhorn/YouTubeKit) выполняется на телефоне, без чужого fallback-сервера, OAuth и сохранённых cookie. YouTube может менять протокол и отклонять запросы. Настроение, жанры и характер поиска — слабый контекст, а не анализ аудио. Мобильное ядро использует собственную модель сходства, сессии и разнообразия; оно не является закрытым алгоритмом Spotify и не полностью совпадает с более крупной настольной моделью.

## Обновление 1.1.0

Контекст YouTube переиспользуется между треками: прогретый запрос не загружает watch-страницу и player JS повторно. Следующие треки и первые результаты поиска/плейлиста подготавливаются заранее; Пульс стартует из готового ранжирования. Индекс признаков, исполнителей и записей общий для главной, Пульса и шести настроений.

Подборки запрашивают русскую и международную музыку. При обновлении существующая библиотека получает новые кандидаты автоматически; региональные слоты не отменяют скрытые треки, жанры и ограничения исполнителей. Признаки языка по тексту слабые: аудио не анализируется. Все сохранения, прослушивания и пропуски продолжают обучать Пульс.

В крупном плеере изображения с короткой стороной меньше 480px заменяются запасным чётким вариантом или градиентом, вместо увеличения маленького превью. Обложки можно отключить в настройках. Для кнопок добавлен короткий отклик с учётом Reduce Motion.

Загрузка больше не ждёт бесконечно: получение адреса ограничено 12 секундами, первый старт буфера — 8 секундами. Повтор запрашивает свежий адрес.

«Настройки → Скорость воспроизведения» показывает реальный интервал до AVPlayer playing, получение адреса и буфер. Замеры новых потоков, кеша и готового трека разделены; ими можно поделиться. Автотесты проверяют контролируемые ответы и нативное аудио, но не доказывают равную ПК скорость живого YouTube на iPhone: сетевой доступ из среды разработки ограничен.

## Изменения 1.0.2

Исправлен фильтр, который отбрасывал основные аудиодорожки с локализованным названием. Если быстрый запрос не даёт аудио, приложение повторяет запрос нативного клиента с контекстом watch-страницы, затем использует WEB. Необязательные поля метаданных больше не мешают загрузке; устаревший player JS обновляется при ошибке подписи. Отказы сохраняют безопасный диагностический код клиента и этапа, без cookie и подписанных URL. Живой YouTube из среды разработки недоступен: автоматические аудиотесты проверяют контролируемые ответы, окончательная проверка требует iPhone.

## Изменения 1.0.1

Нативный аудиоклиент запрашивает поток напрямую без ожидания watch-страницы; web-клиент сохраняет полный путь для совместимости. Аудио извлекается отдельно от видео: используется первый пригодный ответ, медленный второй клиент отменяется. Обработчик подписей и разобранный player JS переиспользуются. Подготовка следующего трека начинается после фактического старта текущего; готовый AVPlayerItem используется и при ручном переключении. Стартовый буфер ограничен 3 секундами; на нестабильной сети возможны паузы при дозагрузке. Начальное уведомление монитора сети больше не отменяет загрузку первого трека.

Мини-плеер занимает собственное место над вкладками, включает сердечко с синхронизацией понравившихся. Обложки используют более крупные изображения, запасные размеры, кеш и декодирование вне главного потока; музыкальные обложки сохраняются вместо замены на видеопревью.

## Проверки и их границы

- **36 тестов Swift-ядра:** парсер музыкального каталога, ссылки, потребление, вкус/пропуски, настроения, интервалы, разнообразие, алиасы артистов, дубликаты записей, совместимость старой библиотеки, формат реального PC-экспорта, миллисекундные даты, Unicode, трёхстороннее объединение и восстановление данных. Дополнительно проверяются качество обложек, региональные подборки, переиспользование индекса и смешанная библиотека из 3000 треков с шестью настроениями.
- **18 тестов аудиопути:** искусственно медленные watch-страница и второй клиент, отмена, неподдерживаемый кодек и ошибочный ответ, расшифровка signature/n, повторное использование разобранного JS с новыми входными данными, кеш контекста клиента и обновление после отказа; без запросов к живому YouTube.
- **74 теста ПК:** включая настоящее Node HTTPS-соединение, одноразовое подключение, Unicode, сохранение токенов/сертификата после перезапуска и объединение истории/плейлистов.
- GitHub Actions **[Build and verify Forma iOS](https://github.com/Astronomial/music/actions/workflows/ios.yml)** собирает Debug для симулятора и Release arm64 для устройства с Xcode. Нативный сценарий запускает приложение в iOS Simulator, проверяет TLS-клиент iOS с сервером ПК, изменение любимого/плейлистов/настроек и четыре автоматических старта нативной очереди после перехода в Safari, затем паузу и возобновление. Дополнительно измеряются границы мини-плеера относительно системной панели вкладок и повторное использование подготовленного трека при ручном переключении. Отчёт входит в артефакт сборки.
- В нативном сценарии используется настоящий **тестовый аудиофайл**, доступный только в Debug Simulator. Release не содержит тестовый плеер, библиотеку или обход проверки URL. Этот сценарий не подтверждает доступность живого YouTube.
- Живой YouTube и физический iPhone здесь недоступны. Звонки, Bluetooth, энергосбережение, блокировка реального экрана, смена сети и длительная цепочка онлайн-треков требуют проверки после установки. Бесшовность переходов и постоянная доступность неофициальных потоков не гарантируются.

## Разработка на Mac

Нужен Xcode 16+; сторонний генератор проекта не нужен. Открой `ios/Forma.xcodeproj`, выбери схему **Forma** и симулятор. Для запуска на устройстве выбери свой Team и идентификатор в Signing & Capabilities.

```sh
swift test --package-path ios/Packages/FormaCore
python3 ios/Scripts/generate_project.py --check
xcodebuild -project ios/Forma.xcodeproj -scheme Forma \
  -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath ios/.derived-data CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- build
python3 ios/Scripts/simulator_smoke.py
xcodebuild -project ios/Forma.xcodeproj -scheme Forma \
  -configuration Release -sdk iphoneos -destination 'generic/platform=iOS' \
  -derivedDataPath ios/.derived-data CODE_SIGNING_ALLOWED=NO build
```

После добавления Swift-файлов/ресурсов обнови проект командой `python3 ios/Scripts/generate_project.py`. GitHub Actions упаковывает `Release-iphoneos/Forma.app` в Payload и IPA; при публикации main размещает IPA и SHA-256 в релизе `ios-v1.1.0`.

| Модуль | Назначение |
| --- | --- |
| `Forma/YouTubeCatalog.swift` | Музыкальный поиск и связанные кандидаты |
| `Forma/YouTubeStreamResolver.swift` | Потоки YouTubeKit, короткий кеш, отмена |
| `Forma/PlaybackController.swift` | Очередь AVQueuePlayer, аудиосессия, системное управление |
| `Forma/AppModel.swift` | Библиотека, подготовка рекомендаций вне главного потока, синхронизация |
| `Forma/SyncClient.swift` | Закреплённый TLS-сертификат ПК и Keychain |
| `Packages/FormaCore` | Модели, парсер, Пульс, разнообразие, объединение и хранение |
| `Scripts/simulator_smoke.py` | Настоящее приложение в симуляторе и тестовый TLS-сервер |
| `Vendor/YouTubeKit` | Закреплённый открытый код, авторство и лицензии |

Плеер живёт на уровне приложения. Воспроизведение после завершения процесса, загрузка YouTube для офлайна и облачная синхронизация через интернет в эту версию не входят. Импорт Яндекса выполняется на ПК; найденные YouTube-версии затем передаются синхронизацией.
