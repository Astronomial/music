# Forma iOS 1.4.2

Нативная **SwiftUI + AVQueuePlayer** для iPhone и iPad, **iOS 17+**, включая iOS 18. YouTube/YouTube Music, персональный Пульс, плейлисты, подборки по настроению и обмен с Windows. Аккаунт YouTube, музыкальная подписка и обязательный сервер не требуются.

**[Скачать IPA для подписи](https://github.com/Astronomial/music/releases/download/ios-v1.4.2/Forma-iOS-1.4.2-unsigned.ipa)** · **[Установка с Windows](INSTALL_WINDOWS.md)** · [Лицензии](THIRD_PARTY.md)

Устанавливай поверх прежней Forma с теми же Apple ID и фактическим Bundle ID Sideloadly. Бесплатная личная подпись обычно действует 7 дней; повторная подпись с прежним идентификатором сохраняет данные.

## Скорость запуска

Три следующих трека буферизуются параллельно сразу после начала текущего. Выбор ещё загружающегося трека передаёт его существующий AVPlayer вместе с накопленным буфером; поздняя отмена старой подготовки не очищает активный плеер. Свежие адреса других треков сохраняются при смене приоритета. Для задержавшегося запроса с кешированным контекстом резервный путь стартует через 250 мс. Подготовка разрешена на мобильной сети и в режиме экономии данных. Холодный запуск остаётся зависимым от ответа YouTube и сети/VPN.

Идентификатор EMBED-клиентов библиотеки теперь использует фактический Bundle ID после подписи вместо адреса постороннего сайта. Нативный аудиопуть iOS не использует Windows iframe; его внутренние заголовки не переписываются.

## Главная и Пульс

Главная и все шесть подборок учитывают общий профиль: любимые треки, выбранные плейлисты, дослушивания, слышимые пропуски и дизлайки. Поиск использует жанры и исполнителей из библиотеки; русскоязычное предпочтение применяется до отбора соседей и разнообразия. Нажатие на рекомендованный трек запускает адаптивный Пульс с настроением выбранной подборки. [Алгоритм](../docs/recommendations.md) · [Проверки](../docs/RELEASE_VALIDATION_1_10.md).

## Обмен с Windows

Google удалён. Нужна **Forma Windows 1.9.0 или новее**, работающий ПК и общая домашняя сеть; ПК может подключаться по Ethernet. Подключение одноразовым кодом защищено TLS с закреплённым сертификатом и токеном телефона в Keychain.

Каждый пакет сначала показывает изменения **На ПК** и **На iPhone**. **Применить на обоих устройствах** на любом одном устройстве подтверждает перенос; второе подтверждение не требуется. Можно отклонить обмен. Запуск, возвращение в Wi-Fi и правки не создают и не применяют новый пакет автоматически. Проверяется лишь решение по уже подготовленному пакету. Оно сохраняется после перезапуска, получение повторяется без дубликатов. Устаревший просмотр требует нового пакета.

Передаются YouTube-плейлисты, лайки/дизлайки, история и контекст обучения, настройки Пульса и признаки звучания. Локальное аудио, пути, ключи, громкость и оформление остаются на устройстве. Правки телефона во время ожидания сохраняются при слиянии. **[Подключение и решение проблем](../docs/WIFI_SYNC.md)**.

Обмен не выполняется через мобильную сеть и не блокирует плеер. VPN можно оставить включённым: для связи с ПК он должен разрешать локальную сеть.

## Подготовка трёх треков

По умолчанию после старта текущего аудио готовится начало до **трёх следующих треков** Пульса и очереди. Ближайший трек остаётся в основной очереди для автоматического перехода; начало трёх следующих треков дополнительно готовится в беззвучных AVQueuePlayer с `preroll`. При выборе готового трека активным становится его уже подготовленный плеер: элемент не переносится между владельцами и поток не запрашивается снова.

Это работает также через мобильную сеть, при включённом режиме экономии данных iOS и VPN. Режим экономии данных не уменьшает глубину и не запрещает аудиозагрузки. В настройках можно вручную выбрать подготовку только следующего трека. Дополнительный трафик разрешён владельцем; целые треки для офлайна приложение не сохраняет.

Смена маршрута/VPN, сброс аудиосервиса, истечение URL и новый выбор удаляют неподходящие буферы. Пауза отменяет незавершённую подготовку. Дополнительные плееры не включают звук, не пишут события слушания и не меняют системный плеер. Ошибка подготовки не останавливает текущую музыку. Произвольный новый результат поиска требует получения потока; скорость зависит от YouTube и маршрута сети.

## Возможности

- Тёмные стеклянные панели, градиенты, палитры, системные шрифты. Мини-плеер занимает место над вкладками, содержит лайк и дизлайк. Крупные обложки с запасными размерами, кешем и декодированием вне главного потока.
- Поиск по названию/артисту и прямой YouTube-ссылке, отмена устаревших результатов. Каталог и расчёт рекомендаций обновляются вне главного потока.
- Фоновая аудиосессия, системные play/pause/next/previous/seek, экран блокировки. Пауза, звонок, наушники, сброс аудиосистемы и смена сети сохраняют намерение пользователя. После смахивания приложения музыка прекращается.
- Пульс: цель 70% находок / 30% знакомой музыки, преимущественно русский язык, новые исполнители рядом со вкусом, контекст сессии и строгий ранний пропуск. Журнал стартов ограничивает повторы артистов; дубликаты записей объединяются. Ошибка потока и перемотка не обучают вкус.
- Общий профиль шести настроений; раскрывающиеся настройки жанров, энергии, вокала, близости открытий, языка, реакции на пропуск, сессии, разнообразия, повторов, артистов и плейлистов. Пульс можно запускать от плейлиста.
- Реальный DSP-анализ первых 24 секунд аудио через AVAssetReader, отдельно от воспроизведения. До 6 МБ на попытку и 12 попыток в час; разрешение мобильной сети и отключение настраиваются. Это ограничение фонового анализа, а не режима экономии данных. [Алгоритм и ограничения](../docs/SOUND_RECOMMENDATIONS.md).
- Плейлисты, любимое, обратимый дизлайк с последним приоритетом в рекомендациях, JSON-экспорт. Атомарное сохранение с резервной копией, ревизии и защита от поздних старых записей.

Неофициальное получение потоков через [YouTubeKit](https://github.com/alexeichhorn/YouTubeKit) выполняется на телефоне без чужого fallback-сервера, cookie и OAuth. Изменения YouTube могут нарушить доступ. Это собственная локальная модель рекомендаций Forma, а не закрытая модель Spotify. Поисковый контекст — слабый сигнал; акустическое сходство учитывается только при наличии измеренных профилей.

## Проверки

- **75 тестов Swift-ядра:** рекомендации, профиль сессии, разнообразие, дубликаты, синхронизация, хранение и восстановление; общие с JavaScript примеры, акустические признаки, обязательное подтверждение пакета и сохранение правок после просмотра.
- **21 тест аудиопути:** медленные и ошибочные ответы, отмена, подписи, срок кеша, отказ и смена сети; без живого YouTube.
- **95 Node-тестов**, пять сценариев интерфейса и настоящий Electron, включая просмотр/отклонение/подтверждение, TLS, восстановление решений и повторное получение.
- Xcode CI собирает Simulator Debug и iPhone Release arm64. Нативный сценарий проверяет TLS с ПК, фоновые переходы, паузу, прерывания, сброс аудиосистемы, быстрые выборы, гонки сохранений/поиска и расположение мини-плеера.
- Отдельный сценарий использует настоящее HTTP-аудио с задержкой тела четыре секунды: готовит три следующих трека на моделируемой мобильной сети с VPN/Low Data Mode, проверяет беззвучность дополнительных плееров и запуск третьего подготовленного трека без повторного получения потока. Контроль начинается от нажатия и требует движения позиции аудио.

Тестовое аудио доступно только в Debug Simulator. Release не содержит проверочную библиотеку или разрешение произвольных URL. Живой YouTube и физический iPhone здесь недоступны; симулятор не подтверждает работу Yota/VPN или скорость любых новых треков. [Отчёт выпуска](../docs/RELEASE_VALIDATION_1_9.md) · [предыдущий аудит стабильности](STABILITY_AUDIT.md).

## Разработка на Mac

Нужен Xcode 16+; сторонний генератор проекта не нужен. Открой `ios/Forma.xcodeproj`, выбери схему **Forma** и симулятор. Для запуска на устройстве выбери свой Team и идентификатор в Signing & Capabilities.

```sh
swift test --package-path ios/Packages/FormaCore
python3 ios/Scripts/generate_project.py --check
xcodebuild -project ios/Forma.xcodeproj -scheme Forma \
  -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath ios/.derived-data CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- build
python3 ios/Scripts/simulator_smoke.py
xcodebuild -project ios/Forma.xcodeproj -scheme Forma \
  -configuration Release -sdk iphoneos -destination 'generic/platform=iOS' \
  -derivedDataPath ios/.derived-data CODE_SIGNING_ALLOWED=NO build
```

После добавления Swift-файлов/ресурсов обнови проект командой `python3 ios/Scripts/generate_project.py`. GitHub Actions упаковывает `Release-iphoneos/Forma.app` в Payload и IPA; при публикации main размещает IPA и SHA-256 в релизе `ios-v1.4.2`.

| Модуль | Назначение |
| --- | --- |
| `Forma/PlaybackController.swift` | Основная очередь, подготовка трёх треков, аудиосессия и управление |
| `Forma/BufferedAudio.swift` | Ограниченный по времени беззвучный preroll |
| `Forma/YouTubeStreamResolver.swift` | Потоки, кеш и отмена |
| `Forma/AppModel.swift` | Библиотека, рекомендации и обмен с подтверждением |
| `Forma/SyncClient.swift` | Локальный TLS-клиент с закреплённым сертификатом |
| `Forma/SoundAnalyzer.swift` | Нативный анализ PCM |
| `Packages/FormaCore` | Рекомендации, объединение, проверка пакетов и хранение |
| `Scripts/simulator_smoke.py` | Проверки настоящего приложения с TLS/HTTP-серверами |
| `Vendor/YouTubeKit` | Закреплённый открытый код и лицензии |

Импорт Яндекса выполняется на ПК; найденные YouTube-версии передаются подтверждённым обменом. Сохранение YouTube для офлайна не предусмотрено.
